## 已确认的问题

### 1. 报告的“复制内容”无法写入系统剪贴板

在前台安装版中打开报告预览并点击复制，再粘贴到隔离草稿，得到的仍是预先设置的 `BIOMAKER_CLIPBOARD_QA_SENTINEL`。

补充测试保留真实 `navigator.clipboard.writeText` 和生产权限处理器，只记录调用结果。页面有焦点，属于 secure context，但 `clipboard-write` 权限为 `denied`，实际写入抛出 `NotAllowedError: Write permission denied`。系统剪贴板仍为旧标记。该诊断能够看到“Could not copy. Select the text manually.”；因此不把此前手工未看到提示扩大为“始终无错误反馈”。

源码位置：[RunView.tsx](../src/RunView.tsx) 的复制函数，以及 [electron/main.ts](../electron/main.ts) 中一律拒绝权限请求/检查的配置。现有通知与日志测试替换了剪贴板 API，无法发现该问题。

证据：[真实 API 诊断](../output/playwright/manual-20261009/clipboard-diagnostic.json)、[错误提示截图](../output/playwright/manual-20261009/06-real-clipboard-diagnostic.png)、[手工粘贴结果](../output/playwright/manual-20261009/05-clipboard-still-sentinel.png)。第一次补充诊断因英文按钮名称不匹配而超时，已单独保留，修正测试选择器后得到上述结果。

### 2. 小窗口、长路径下，设置往返会把整体顶栏卷出屏幕

在 1180×780 窗口显示带长数据/输出路径的历史实验，然后打开设置并切换语言，顶栏和部分实验标题会被裁切。中文状态也已经存在超高布局；英文并非唯一触发条件。

| 时点 | 窗口高度 | shell 内容高度 | shell 纵向滚动 | 顶栏 top |
| --- | ---: | ---: | ---: | ---: |
| 打开设置前 | 780 | 919 | 0 | 0 |
| 打开设置后 | 780 | 919 | 139.5 | -139.5 |
| 返回英文实验页 | 780 | 916 | 136.5 | -136.5 |

body 未滚动，偏移发生在 `.app-shell`。其固定高度没有约束隐式 grid 行，右侧 `.inspector` 的内容使该行高于窗口；显示底部设置控件后，整个 shell 被滚动。只重置 `.workspace-content` 无法修复外层偏移。已有断言仅检查内层面板和横向溢出，未检测这个问题。

证据：[测量摘要](../output/playwright/manual-20261009/layout-finding.json)、[完整祖先几何记录](../output/playwright/manual-20261009/navigation-diagnostic/ancestor-geometry.jsonl)、[本轮裁切截图](../output/playwright/manual-20261009/suites/run-navigation/evidence-conflict-en.png)。修复应约束 grid 行与 inspector 的最小高度，并补充顶栏及底栏相对真实视口的断言。

### 3. 明确关闭最终重训的成功实验仍被提示“部分文件或记录不完整”

本轮成功任务显示“未启用最终重训”，但结果页同时显示总括的不完整警告。结果收据中其余四个主要文件均可用，唯一警告是 `final_retrain_result_missing`。该文件在明确关闭重训时本就不会生成。

[result_overview.py](../service/result_overview.py) 已正确判定 `disabled / explicit_disabled`，但又无条件为缺失文件增加 warning；[RunResults.tsx](../src/RunResults.tsx) 将它显示为不完整提示。应区分预期的可选文件缺失与真正的损坏、读取失败或状态冲突。

证据：[本轮工作流的 result_overview](../output/playwright/manual-20261009/workflow.json)。现有用例只验证 disabled 状态，没有断言这个多余警告。

### 4. 草稿删除失败时错误标题仍写成草稿保存问题

在隔离测试中模拟“任务已入队，但源草稿删除失败”，准确的提示旁仍出现泛化的 `Draft save issue` 标题，容易让人误以为任务未提交。此次现有 toast 回归再次覆盖该故障场景；这是故障注入结果，不是用户草稿实际删除失败。

证据：[本轮故障截图](../output/playwright/manual-20261009/suites/toast-feedback/04-submit-failure.png)。应按保存、重命名、复制和删除等操作显示对应标题。
